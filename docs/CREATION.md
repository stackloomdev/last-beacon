# 创作记录 · Creation notes

日期：2026-09-07。

创作者：stackloomdev。开发环境：Codex。参与模型：GPT-6 Astra。

## 起点

创作者希望为 `MartinDelophy/awesome-gpt-6-astra` 的「策略与模拟」分类贡献一款可以实际试玩的游戏。经过比较塔防、RPG、平台跳跃等方向，选择了具有供电连接机制的微缩海岛塔防《最后的灯塔》。

## 模型参与内容

- 将玩法范围收敛为一张地图、三种炮塔、中继站、十波敌人和一个 Boss。
- 实现独立战斗规则，包括目标选择、范围伤害、减速、漏怪、胜负、超频及资源经济。
- 实现基于图遍历的供电连接，以及按建造顺序分配有限电力的规则。
- 通过 Canvas 2D 几何绘制岛屿、植被、灯塔、设施、敌人和战斗特效。
- 通过 Web Audio 合成音效，没有使用下载的音频样本。
- 实现中英双语界面、键盘控制、手机布局、无依赖本地服务器和单文件构建。
- 编写并运行规则测试和完整战役回归；结合独立审阅和浏览器操作修复问题。

## 迭代过程

第一版战役模拟显示，少量初级火力也能轻松渡过大部分波次，因此提高了后期敌人的血量压力。重新验证了一套使用真实预算的混合防线能够击败最终 Boss，同时仅保留初始免费炮塔的策略会失败。

浏览器检查和独立代码审阅发现并修复了窄窗口下重开入口不可见、侧栏与按钮叠压、按钮聚焦时空格快捷键失效、重开继承旧暂停状态，以及失败波次被标记为已完成等问题。

随后按创作者要求增加中文 / English 即时切换，统一静态界面、动态设施面板、画布标签和结算文案；语言偏好保存在当前浏览器，切换不重置正在进行的守望。同步调整英文在手机上的排版，并把双语支持内嵌到单文件版。

## 归因边界

这份记录是本作品的创作说明。开发经历了多轮修改，**不是一次提示词生成**。自动化战役通过不等同于任意策略都能过关，浏览器检查不代表已覆盖所有设备。尚未发布的试玩网址、公开源码地址和 PR 状态不应被写成已完成。
